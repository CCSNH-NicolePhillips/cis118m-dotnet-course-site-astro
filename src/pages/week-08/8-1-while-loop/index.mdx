## 🧠 What Is a While Loop?

A **while loop** checks a condition **before** each iteration. If the condition is `true`, the body executes. If it's `false`, the loop is skipped entirely:

```csharp
int count = 1;

while (count <= 5) {
    Console.WriteLine($"Iteration {count}");
    count++;  // Progress statement — CRITICAL!
}

Console.WriteLine("Loop complete.");
```

**Output:**
```
Iteration 1
Iteration 2
Iteration 3
Iteration 4
Iteration 5
Loop complete.
```

The `while` loop is a **pre-check** loop — it checks the gate <strong>before</strong> entering. If the condition is already false when the loop starts, the body <strong>never executes</strong>.

## ⚠️ The Infinite Loop Trap

The most dangerous mistake in loop programming is forgetting the **progress statement** — the line that moves the condition toward `false`:

```csharp
// ❌ INFINITE LOOP — count never changes!
int count = 1;
while (count <= 5) {
    Console.WriteLine($"Stuck at {count}");
    // Missing: count++;  ← Without this, count stays 1 FOREVER
}
```

This program will print "Stuck at 1" forever, consuming CPU and potentially freezing your system.

<div class="architect-rule">

#### ⚠️ Architect's Rule: Every Loop Must Have a Progress Statement

Before writing ANY while loop, ask: **"What changes inside this loop to make the condition eventually false?"** If you can't answer that question, your loop is broken.

The three essential parts of every while loop:
1. **Initialization** — set up the loop variable (`int count = 1`)
2. **Condition** — the gate that controls entry (`count <= 5`)
3. **Progress** — the change that moves toward exit (`count++`)

</div>

## 🔍 Pre-Check Behavior: The Closed Gate

Because `while` checks the condition **first**, it's possible for the loop body to never execute:

```csharp
int temperature = 72;  // Already at target

while (temperature < 68) {
    Console.WriteLine("Heating...");
    temperature++;
}

Console.WriteLine($"Temperature is {temperature}°F — comfortable!");
// Output: Temperature is 72°F — comfortable!
// The loop body NEVER ran because 72 is not < 68
```

This is the **pre-check** nature of `while` — the gate must be open for the body to run.

<div class="pro-tip">
  <h4>💡 Pre-Check = Conditional Entry</h4>
  <p>Think of a <code>while</code> loop like a security gate that checks your badge <strong>before</strong> you enter. If your badge is invalid (condition is false), you never get inside. This is different from <code>do-while</code> (Section 8.2), which lets you in first and checks your badge when you try to leave.</p>
</div>

class Program
{
    static void Main()
    {
        Console.WriteLine("=== SENSOR LOOP: COUNTER ===");
        
        // 1. Initialization
        int count = 1;
        int threshold = 10;
        
        // 2. Condition (pre-check)
        while (count <= threshold) {
            // Loop body
            Console.WriteLine($"  Reading #{count}: Sensor active");

            count++;
        }

        Console.WriteLine("\\n=== PRE-CHECK DEMO ===");
        int x = 100;
        while (x < 10) {
            Console.WriteLine("This will NEVER print!");
            x++;
        }
        Console.WriteLine($"  x = {x} — loop body was skipped entirely.");
    }
}`}
  instructions="Run the code, then try changing threshold to 5. Then set count's initial value to 15 — watch the loop get skipped entirely because the pre-check fails!"

## 🧮 Loop Patterns: Accumulation

Loops aren't just for counting — they're the engine for **accumulating** values:

```csharp
// Sum of numbers from 1 to N
int n = 100;
int sum = 0;
int i = 1;

while (i <= n) {
    sum += i;   // Accumulate each number
    i++;
}

Console.WriteLine($"Sum of 1 to {n} = {sum}");
// Output: Sum of 1 to 100 = 5050
```

## 📐 Common While Loop Mistakes

<div class="styled-table-container">
  <table>
    <thead>
      <tr>
        <th>Mistake</th>
        <th>Problem</th>
        <th>Fix</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td><strong>Missing progress</strong></td>
        <td>Loop runs forever (infinite loop)</td>
        <td>Always include <code>count++</code> or equivalent change</td>
      </tr>
      <tr>
        <td><strong>Off-by-one</strong></td>
        <td>Loop runs one too many or one too few times</td>
        <td>Trace the first and last iteration carefully</td>
      </tr>
      <tr>
        <td><strong>Wrong direction</strong></td>
        <td><code>count--</code> when counting up → infinite loop</td>
        <td>Progress must move <em>toward</em> the exit condition</td>
      </tr>
      <tr>
        <td><strong>Uninitialized variable</strong></td>
        <td>Loop variable has no starting value</td>
        <td>Always initialize before the loop: <code>int i = 0;</code></td>
      </tr>
    </tbody>
  </table>

**Output**: `Total: 30`

**Trace**:
