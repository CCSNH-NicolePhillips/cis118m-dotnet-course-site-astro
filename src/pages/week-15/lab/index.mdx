# Lab 15: Architecture Review - Global System Design

<div class="deadline-banner">
  <span class="deadline-label">Due:</span>
  <span>Saturday, May 9 at 11:59 PM Eastern</span>
</div>

Before the final submission is frozen, document the architecture that will hold the system together. This lab is the design review. The goal is to prove that the capstone has a clear class model, controlled state boundaries, list ownership, and modular method decomposition before the final grading pass.

---

## Required Sections

Your submission must include all of the following sections:

1. <strong>System statement:</strong> one paragraph explaining what the program does and which operator actions it supports.
2. <strong>Class architecture:</strong> the custom class or classes in the project and the responsibility of each one.
3. <strong>Property contracts:</strong> which properties are validated, what rules they enforce, and where invalid state is rejected.
4. <strong>Collection management:</strong> how <code>List&lt;T&gt;</code> stores the objects, and which methods add, search, update, remove, or report them.
5. <strong>Method inventory:</strong> the core methods in the system, their return types, and which caller uses each result.
6. <strong>Risk register:</strong> the three most likely integration failures and the mitigation for each one.
