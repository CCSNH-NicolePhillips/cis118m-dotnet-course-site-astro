The final project is the capstone system integration submission. The grading decision is based on whether the project demonstrates a coherent design, controlled runtime behavior, and visible proof that the integrated system works.

<div class="grading-note">
  <p>The Week 15 recorded grade belongs in the Final Project category.</p>
  <p>There is no separate Week 15 lab, homework, quiz, or participation grade. If your instructor wants a written final memo, include it inside this final project package.</p>
</div>

## Required Technical Evidence

<div class="styled-table-container">
  <table>
    <thead>
      <tr>
        <th scope="col">Mandatory requirement</th>
        <th scope="col">What the instructor must be able to verify</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td>Custom class architecture</td>
        <td>At least one real domain class exists and owns meaningful responsibility beyond passive storage.</td>
      </tr>
      <tr>
        <td>Encapsulated properties</td>
        <td>State protection exists through validated properties, controlled constructors, or equivalent guarded mutation boundaries.</td>
      </tr>
      <tr>
        <td>List-based data management</td>
        <td>The system manages multiple domain objects through a <code>List&lt;T&gt;</code> and performs lifecycle operations on that list.</td>
      </tr>
      <tr>
        <td>Modular method logic</td>
        <td>The core workflow is decomposed into named methods with clear input and output responsibilities.</td>
      </tr>
    </tbody>
  </table>
</div>

---

## Minimum Runtime Capabilities

- The program starts cleanly and presents a readable operator path.
- Invalid input is handled without crashing the application or corrupting object state.
- The project demonstrates at least one add or create workflow and at least one retrieval, search, or report workflow.
- Output is labeled clearly enough that an instructor can verify feature behavior without reverse-engineering the code.
- If file persistence is included, both first-run behavior and reload behavior are demonstrated.

---

## Submission Package

1. Source code for the final project.
2. Two to four screenshots or output captures showing the major workflows.
3. A short run sequence or demonstration guide for the instructor.
4. Any supporting data files required to reproduce the system state.
5. If assigned, a written final memo or deployment guide included inside the final project package rather than submitted as a separate grade.

---

## Recovery Window Boundary

The Week 15 recovery window covers missing assignments and quizzes from Weeks 01-14 only, with a maximum score of 70% on recovered work. It does not replace the final project deadline or lower the expectation for the capstone submission.
