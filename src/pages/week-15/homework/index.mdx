## Reflection Prompt

In 3-5 sentences per question, answer all prompts:

1. <strong>Architecture summary:</strong> Explain how your custom class, validation rules, <code>List&lt;T&gt;</code> workflow, and named methods interact during one normal user scenario.
2. <strong>Verification matrix:</strong> Describe at least four tests you will run before submission, including at least two edge cases that could fail if the system is weakly designed.
3. <strong>Recovery-window triage:</strong> If you still have missing work from Weeks 01-14, identify exactly which items you will recover during the Week 15 window and how you will protect your final-project schedule. If you have no missing work, state that explicitly.
4. <strong>Instructor runbook:</strong> Write the exact demonstration path an instructor should follow to verify your project in under five minutes, including which menu actions or commands reveal the strongest architectural evidence.

<div class="architect-rule">
  <h3>Senior Architect Expectation</h3>
  <p>
    Write this like a deployment handoff document. Use concrete language: method names, class names, validation rules, test cases, and the exact instructor workflow. Avoid vague claims such as "it works" or "the code is organized."
  </p>
</div>
