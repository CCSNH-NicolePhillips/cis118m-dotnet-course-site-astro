## 🚫 The Type Mismatch Problem

Why doesn't this work?

```csharp
// ❌ THIS WILL NOT COMPILE
int x = Console.ReadLine();  // ERROR: Cannot implicitly convert string to int
```

<div class="error-box">
  <div class="error-icon" aria-hidden="true">⚠️</div>
  <div class="error-content">
    <h4>Compiler Error CS0029</h4>
    <p><code>Cannot implicitly convert type 'string' to 'int'</code></p>
    <p>C# is <strong>strongly typed</strong>. Text and numbers are fundamentally different data types. You cannot assign one to the other without explicit conversion.</p>
  </div>
</div>

## 📊 The Parse Method Family

The .NET Framework provides parsing methods for each numeric type. Choose based on your data requirements:

<div class="styled-table-container">
  <table>
    <thead>
      <tr>
        <th>Method</th>
        <th>Returns</th>
        <th>Use Case</th>
        <th>Example</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td><code>int.Parse()</code></td>
        <td><code>int</code></td>
        <td>Whole numbers (counts, IDs, quantities)</td>
        <td><code>int.Parse("42")</code> → <code>42</code></td>
      </tr>
      <tr>
        <td><code>double.Parse()</code></td>
        <td><code>double</code></td>
        <td>Measurements, scientific data, percentages</td>
        <td><code>double.Parse("3.14")</code> → <code>3.14</code></td>
      </tr>
      <tr class="highlight-row">
        <td><code>decimal.Parse()</code></td>
        <td><code>decimal</code></td>
        <td><strong>💰 MONEY & FINANCIAL DATA</strong></td>
        <td><code>decimal.Parse("19.99")</code> → <code>19.99m</code></td>
      </tr>
      <tr>
        <td><code>bool.Parse()</code></td>
        <td><code>bool</code></td>
        <td>True/false flags</td>
        <td><code>bool.Parse("true")</code> → <code>true</code></td>
      </tr>
    </tbody>
  </table>
</div>

<div class="critical-callout">
  <div class="callout-icon" aria-hidden="true">💰</div>

    <h4>The Architect's Rule: decimal for Financial Data</h4>
    <p>
      <strong>decimal</strong> is the architect's choice for any financial calculation—prices, salaries, budgets, interest rates. Remember the 0.1 + 0.2 problem from Week 3: <code>double</code> cannot exactly represent many decimal fractions, leading to penny errors that compound into millions lost.
    </p>

## 💻 Parse in Action

<TryItNowRunner 
  starterId="week-05-parse-demo" 
  height={450}
  code={`using System;

class Program
{
    static void Main()
    {
        // String input (simulating Console.ReadLine)
        string ageText = "25";
        string heightText = "5.9";
        string salaryText = "75000.50";
        
        // Parse to appropriate types
        int age = int.Parse(ageText);
        double height = double.Parse(heightText);
        decimal salary = decimal.Parse(salaryText);  // Financial = decimal!
        
        // Now we can do math
        int ageNextYear = age + 1;
        decimal monthlyPay = salary / 12;
        
        Console.WriteLine($"Current age: {age}, Next year: {ageNextYear}");
        Console.WriteLine($"Height: {height} feet");
        Console.WriteLine($"Monthly pay: {monthlyPay:C}");
    }
}`}
  instructions="Run this to see parsing in action. Notice how decimal is used for salary (money) and int for age (whole number)."
