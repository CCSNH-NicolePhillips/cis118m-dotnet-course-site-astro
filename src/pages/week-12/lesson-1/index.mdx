## Defining a Class: The Syntax

A class definition starts with the `class` keyword followed by a PascalCase name. Inside the curly braces, you declare the data the type will hold:

```csharp
class Student {
    public string Name { get; set; }
    public int Id { get; set; }
    public double Gpa { get; set; }
}
```

This code does not create a student. It defines what a `Student` **is** — a data type with three properties. Think of it as an architectural blueprint: the blueprint describes the building, but no building exists until someone constructs one.

## Access Modifiers: public vs private

Access modifiers control **who can see and use** the members of a class. At the introductory level, you need two:

<div class="styled-table-container">
<table>
<thead>
<tr><th scope="col">Modifier</th><th scope="col">Visibility</th><th scope="col">When to Use</th></tr>
</thead>
<tbody>
<tr><td><code>public</code></td><td>Accessible from anywhere — Main, other classes, other methods</td><td>Properties and methods that the outside world needs to read or call</td></tr>
<tr><td><code>private</code></td><td>Accessible only inside the class itself</td><td>Internal data or helper logic that should not be exposed</td></tr>
</tbody>
</table>
</div>

```csharp
class BankAccount {
    public string Owner { get; set; }       // Anyone can read/write the owner name
    private decimal balance;                 // Only the class itself can touch the balance

    public decimal GetBalance() {            // Public method provides controlled access
        return balance;
    }

    public void Deposit(decimal amount) {    // Public method modifies the private field
        balance += amount;
    }
}
```

The `private` modifier is the default in C# — if you omit the access modifier, the member is private. This is an important safety mechanism: data that should not be changed directly from outside the class stays hidden behind `private`.

<img src="/media/week%2012/12.1/Access%20Modifiers.jpeg" alt="Access Modifiers diagram — a class box with two zones: a public zone at the top with properties visible to outside code through a green open gate, and a private zone at the bottom with fields behind a red locked gate, showing that Main can only reach the public members" style="max-width: 100%; border-radius: 12px; margin: 24px 0;" />

<div class="architect-rule">

### Architect's Rule: Start Private, Expose Only What Is Needed

In professional software, the default posture is privacy. Every field starts as private. You expose a public interface — properties and methods — only for data that the outside world genuinely needs to access. This principle is called **encapsulation**: the class controls access to its own data. For this introductory course, most of your properties will be `public` with `{ get; set; }`, but understanding the role of `private` is essential for reading and reasoning about real-world code.

</div>

## Fields vs Properties

C# classes can hold data in two ways: **fields** and **properties**. Both store values, but they differ in how they control access:

<div class="component-cards">
  <div class="component-card">
    <h3>Fields</h3>
    <p>Raw variables declared directly inside the class. No access control beyond the modifier. If a field is <code>public</code>, anyone can read or write it without restriction.</p>
    <code>public string name;</code>
    <p style="margin-top: 8px; font-size: 0.85rem; opacity: 0.7;">Direct access — no validation, no interception. Used for simple internal storage.</p>
  </div>
  <div class="component-card">
    <h3>Properties</h3>
    <p>Managed accessors with <code>get</code> and <code>set</code>. The property can include logic — validation on set, computation on get, or restricted access (read-only).</p>
    <code>public string Name &#123; get; set; &#125;</code>
    <p style="margin-top: 8px; font-size: 0.85rem; opacity: 0.7;">Controlled access — the class decides how data is read and written. Industry standard.</p>
  </div>
</div>

<img src="/media/week%2012/12.1/Fields%20vs%20Properties.jpeg" alt="Fields vs Properties comparison — left side shows a raw public field with direct uncontrolled access, right side shows an auto-implemented property with get and set accessors providing a controlled gateway to a hidden backing field" style="max-width: 100%; border-radius: 12px; margin: 24px 0;" />

**In this course, use auto-implemented properties** (`{ get; set; }`) for all class data. This is the standard practice in modern C#. The compiler generates a hidden backing field automatically — you get the safety of a property without writing extra code.

```csharp
// PREFERRED: auto-implemented property
public string Name { get; set; }

// ALSO VALID but verbose: property with explicit backing field
private string name;
public string Name {
    get { return name; }
    set { name = value; }
}
```

Both versions produce identical behavior. The auto-implemented version is shorter and cleaner — the compiler handles the backing field for you.

## Class Placement in Your Program

For this course, define your classes **inside the same file as Main**, but **outside the Main method**. In C# 10+ with top-level statements, the class goes after your Main code:

```csharp
// Main code (top-level statements)
Student s = new Student();
s.Name = "Ada Lovelace";
s.Id = 1001;
s.Gpa = 3.9;
Console.WriteLine($"{s.Name} (ID: {s.Id}) — GPA: {s.Gpa}");

// Class definition — after the top-level statements
class Student {
    public string Name { get; set; }
    public int Id { get; set; }
    public double Gpa { get; set; }
}
```

The class definition can appear after the top-level statements. The compiler resolves types regardless of declaration order within the file.

## A Complete Example: Defining and Using a Class

```csharp
// Create a Product object and set its properties
Product laptop = new Product();
laptop.Name = "Developer Laptop";
laptop.Price = 1299.99m;
laptop.InStock = true;

Console.WriteLine($"Product: {laptop.Name}");
Console.WriteLine($"Price: {laptop.Price:C}");
Console.WriteLine($"Available: {laptop.InStock}");

// Class definition
class Product {
    public string Name { get; set; }
    public decimal Price { get; set; }
    public bool InStock { get; set; }
}
```

Output:
```
Product: Developer Laptop
Price: $1,299.99
Available: True
```

The `Product` class defines a type with three properties. The code in Main creates one `Product` object, assigns values via the dot operator, and displays them. The class is the blueprint — the object is the actual data.
