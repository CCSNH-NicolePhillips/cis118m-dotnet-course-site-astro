<DueDateBanner week={12} />

<div class="mission-brief">
  <h2>Mission Brief: Building Your Own Data Types</h2>
  <p>
    Every program you have written so far uses built-in types — <code>int</code>, <code>string</code>, <code>double</code>, <code>bool</code>. These types represent single values: one number, one name, one true/false flag. But real software models <strong>entities</strong> — a student has a name, an ID, and a GPA. A product has a title, a price, and a stock count. No single built-in type can represent these compound structures. This week, you learn to define your own data types using the <code>class</code> keyword.
  </p>
  <p>
    A class is a <strong>blueprint</strong>. It describes the shape of a data type — what fields it contains, what properties expose those fields, and what access modifiers control visibility. The class itself holds no data. To get actual data, you create an <strong>object</strong> — an instance of the class — using the <code>new</code> keyword. Each object is independent: it carries its own copy of the data defined by the blueprint.
  </p>
</div>

## The Type System Shift: From Primitives to Custom Types

Until now, every variable in your programs has used a built-in primitive type — `int`, `double`, `string`, `bool`. These types are defined by the C# language itself. This week, you cross a fundamental boundary: **you define your own types**. The `class` keyword lets you create a new data type that groups related values into a single unit.

## Senior Architect Perspective

<div class="architect-rule">

### The Class Is the Fundamental Unit of Object-Oriented Design

Every professional C# application is built from classes. A class defines a type — a contract that says: "Any object of this type will have these properties and these behaviors." When you write `class Student`, you are telling the compiler: "I am defining a new data type called Student." From that point on, `Student` is as valid a type as `int` or `string`. You can declare variables of type `Student`, pass `Student` objects to methods, return them from methods, and store them in collections.

The decision of **what classes to define** and **what data each class holds** is the first and most important architectural decision in any C# project. Get the class design right, and the rest of the code follows naturally. Get it wrong, and every feature built on top of that foundation will be harder than it should be.

</div>

<div class="pro-tip">
  <h3>Phase IV: Object-Oriented Thinking</h3>
  <p>You have been writing procedural code — variables, conditions, loops, methods. This week marks the shift to <strong>object-oriented programming</strong>. Instead of managing dozens of loose variables, you define a class that bundles related data together. Instead of passing five separate parameters to a method, you pass one object. This is how every modern C# application is structured. The concepts this week — classes, properties, objects, the <code>new</code> keyword — are the foundation for everything that follows.</p>
