## 🧠 The Switch Syntax

A switch statement takes **one expression** and compares it against multiple `case` labels:

```csharp
switch (variable) {
    case value1:
        // Code for value1
        break;
    case value2:
        // Code for value2
        break;
    case value3:
        // Code for value3
        break;
    default:
        // Code when no case matches
        break;
}
```

Each `case` checks for an exact match. When a match is found, that block runs. The `break` statement exits the switch — **without it, C# will give a compile error** (unlike some other languages that "fall through").

## 🔀 Switch vs. else-if: A Side-by-Side

Here's the same logic written both ways:

```csharp
// ❌ else-if chain — works but repetitive
if (day == "Monday") {
    Console.WriteLine("Start of work week");
} else if (day == "Friday") {
    Console.WriteLine("Almost the weekend!");
} else if (day == "Saturday" || day == "Sunday") {
    Console.WriteLine("Weekend!");
} else {
    Console.WriteLine("Midweek grind");
}
```

```csharp
// ✅ Switch — cleaner for matching ONE variable against values
switch (day) {
    case "Monday":
        Console.WriteLine("Start of work week");
        break;
    case "Friday":
        Console.WriteLine("Almost the weekend!");
        break;
    case "Saturday":
    case "Sunday":
        Console.WriteLine("Weekend!");
        break;
    default:
        Console.WriteLine("Midweek grind");
        break;
}
```

Notice how `case "Saturday":` and `case "Sunday":` **stack** — when two cases should do the same thing, list them together without a `break` between them.

<div class="pro-tip">
  <h4>💡 When to Use Switch vs. else-if</h4>
  <p><strong>Switch</strong>: Comparing one variable against specific discrete values (strings, ints, enums). <strong>else-if</strong>: Complex conditions with ranges (<code>&gt; 90</code>), multiple variables, or boolean logic (<code>&&</code>, <code>||</code>).</p>
</div>

                break;
            default:
                Console.WriteLine("⚠️ INVALID — Severity must be 1-4");

## 📐 Switch Rules and Gotchas

<div class="styled-table-container">
  <table>
    <thead>
      <tr>
        <th>Rule</th>
        <th>Details</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td><strong>break is required</strong></td>
        <td>C# requires <code>break</code> (or <code>return</code>) at the end of each case. No accidental fall-through.</td>
      </tr>
      <tr>
        <td><strong>Cases must be constants</strong></td>
        <td>Case labels must be compile-time constants — literals like <code>1</code>, <code>"hello"</code>, not variables.</td>
      </tr>
      <tr>
        <td><strong>Stacking cases</strong></td>
        <td>Multiple cases can share one block: list them vertically without break between them.</td>
      </tr>
      <tr>
        <td><strong>default is optional</strong></td>
        <td>But always include it — it catches unexpected values and prevents silent failures.</td>
      </tr>
      <tr>
        <td><strong>Works with int, string, char, enum</strong></td>
        <td>Switch works great with discrete types. It does <strong>not</strong> work with ranges like <code>&gt; 90</code>.</td>
      </tr>
    </tbody>
  </table>
</div>

<div class="architect-rule">

#### ⚠️ Architect's Rule: Always Include default

Even if you think you've covered every possible value, add a `default` case. New values may be added later, and `default` catches them instead of silently doing nothing.

</div>

#### 🎯 Predict the Output: Switch Traps

What does this code print?

```csharp
string color = "RED";

switch (color) {
    case "red":
        Console.WriteLine("Lowercase red");
        break;
    case "RED":
        Console.WriteLine("Uppercase RED");
        break;
    case "Red":
        Console.WriteLine("Mixed case Red");
        break;
    default:
        Console.WriteLine("Unknown color");
        break;
}
```

<details class="predict-reveal">
<summary>Reveal Answer</summary>
<div class="predict-answer">

**Output**: `Uppercase RED`

Switch compares with **exact equality**, including case sensitivity! `"RED"` does NOT match `"red"` or `"Red"`. This is why production code often uses `.ToLower()` before switching:

```csharp
switch (color.ToLower()) {
    case "red": ...  // Now matches "RED", "Red", "rEd", etc.
}
```

🔑 **Key takeaway**: String switch is case-sensitive! Always normalize case before comparing if user input is involved.
</div>
</details>
