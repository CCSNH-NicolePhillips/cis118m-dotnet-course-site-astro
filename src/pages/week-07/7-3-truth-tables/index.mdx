## 🧠 The Three Fundamental Gates

Every boolean expression in C# is built from three fundamental operations: **AND**, **OR**, and **NOT**. A truth table shows the output for **every** possible input combination.

### NOT (`!`) — The Inverter

The simplest gate — it has **one** input and flips it:

```
╔═══════════════════════════╗
║       NOT (!) Gate        ║
╠═══════════════════════════╣
║   Input A    │  !A        ║
║   ─────────  │  ──────    ║
║   true       │  false     ║
║   false      │  true      ║
╚═══════════════════════════╝
```

```csharp
bool isLocked = true;
bool isUnlocked = !isLocked;  // false — the NOT flips it
```

### AND (`&&`) — Both Must Pass

The AND gate requires **both** inputs to be true:

```
╔═══════════════════════════════════════╗
║          AND (&&) Gate                ║
╠═══════════════════════════════════════╣
║   A       │  B       │  A && B       ║
║   ──────  │  ──────  │  ──────       ║
║   false   │  false   │  false        ║
║   false   │  true    │  false        ║
║   true    │  false   │  false        ║
║   true    │  true    │  true   ✅    ║
╚═══════════════════════════════════════╝
```

Only **one row** produces `true` — the case where both A and B are true.

### OR (`||`) — At Least One Must Pass

The OR gate needs **at least one** input to be true:

```
╔═══════════════════════════════════════╗
║          OR (||) Gate                 ║
╠═══════════════════════════════════════╣
║   A       │  B       │  A || B       ║
║   ──────  │  ──────  │  ──────       ║
║   false   │  false   │  false        ║
║   false   │  true    │  true   ✅    ║
║   true    │  false   │  true   ✅    ║
║   true    │  true    │  true   ✅    ║
╚═══════════════════════════════════════╝
```

Only **one row** is `false` — the case where both A and B are false.

<div class="pro-tip">
  <h4>💡 Memory Trick</h4>
  <p><strong>AND</strong> is pessimistic — looks for a reason to say NO. <strong>OR</strong> is optimistic — looks for a reason to say YES.</p>
</div>

## 📐 Building Complex Truth Tables

Real systems combine multiple operators. For example, a system that grants access when the user **is an admin** OR (**is logged in** AND **has permission**):

```csharp
bool accessGranted = isAdmin || (isLoggedIn && hasPermission);
```

To verify this, you build a truth table with **all 8 combinations** (2³ = 8 rows for 3 variables):

```
╔═══════════════════════════════════════════════════════════════════╗
║   isAdmin  │  isLoggedIn  │  hasPerm  │  loggedIn && hasPerm  │  Result   ║
║   ───────  │  ──────────  │  ───────  │  ───────────────────  │  ──────   ║
║   false    │  false       │  false    │  false                │  false    ║
║   false    │  false       │  true     │  false                │  false    ║
║   false    │  true        │  false    │  false                │  false    ║
║   false    │  true        │  true     │  true                 │  true  ✅ ║
║   true     │  false       │  false    │  false                │  true  ✅ ║
║   true     │  false       │  true     │  false                │  true  ✅ ║
║   true     │  true        │  false    │  false                │  true  ✅ ║
║   true     │  true        │  true     │  true                 │  true  ✅ ║
╚═══════════════════════════════════════════════════════════════════╝
```

Notice: Admins **always** get access (bottom 4 rows). Non-admins only get access when **both** logged in AND have permission (row 4).

<div class="architect-rule">

#### ⚠️ Architect's Rule: Verify Before You Code

Before writing a complex boolean expression, build its truth table on paper. If **any row** produces an unexpected result, fix the logic **before** coding it. A truth table takes 2 minutes. Debugging wrong logic in production takes 2 hours.

</div>

## 🔬 Try It: Truth Table Generator

Build a program that generates a truth table for all combinations of two boolean variables:

<TryItNowRunner 
  starterId="week-07-lesson-1" 
  height={520}
  code={`using System;

class Program
{
    static void Main()
    {
        Console.WriteLine("╔═══════════════════════════════════════════════════╗");
        Console.WriteLine("║         COMPLETE TRUTH TABLE MATRIX              ║");
        Console.WriteLine("╠═══════════════════════════════════════════════════╣");
        Console.WriteLine("║  A      │  B      │  A && B  │  A || B  │  !A   ║");
        Console.WriteLine("║  ─────  │  ─────  │  ──────  │  ──────  │  ──── ║");
        
        // Generate all 4 combinations
        bool[] values = { false, true };
        
        foreach (bool a in values) {
            foreach (bool b in values) {
                string aStr = a.ToString().PadRight(5);
                string bStr = b.ToString().PadRight(5);
                string andStr = (a && b).ToString().PadRight(6);
                string orStr = (a || b).ToString().PadRight(6);
                string notStr = (!a).ToString().PadRight(4);
                
                Console.WriteLine($"║  {aStr}  │  {bStr}  │  {andStr}  │  {orStr}  │  {notStr} ║");
            }
        }
        
        Console.WriteLine("╚═══════════════════════════════════════════════════╝");
        
        Console.WriteLine();
        Console.WriteLine("Key insight: AND has 1 true row, OR has 1 false row!");
    }
}`}
  instructions="Run to see the complete truth table for AND, OR, and NOT. Count the true/false rows — AND has only 1 true, OR has only 1 false!" 
/>

<div class="experiment-box">

#### 🧪 Experiment: Extend the Truth Table

Try modifying the code above to explore more operators:

1. **Add XOR column**: XOR is true when inputs are **different**. Add `(a != b)` as a new column. How many true rows does it have?
2. **Add NAND column**: NAND is the opposite of AND. Add `!(a && b)` as a column. Compare it to the AND column!
3. **Add NOR column**: NOR is the opposite of OR. Add `!(a || b)`. Only ONE row is true — which one?
4. **Count the true rows**: AND=1, OR=3, XOR=2, NAND=3, NOR=1. Notice the symmetry!

💡 **Discovery**: NAND and NOR are the "inverse" of AND and OR. Every logic gate has a mirror image that flips all outputs!

</div>

## 🧩 Operator Precedence

When combining `!`, `&&`, and `||` in one expression, C# follows a strict evaluation order:

<div class="styled-table-container">
  <table>
    <thead>
      <tr>
        <th>Priority</th>
        <th>Operator</th>
        <th>Name</th>
        <th>Evaluates</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td><strong>1st</strong> (highest)</td>
        <td><code>!</code></td>
        <td>NOT</td>
        <td>Flips a single value</td>
      </tr>
      <tr>
        <td><strong>2nd</strong></td>
        <td><code>&&</code></td>
        <td>AND</td>
        <td>Both must be true</td>
      </tr>
      <tr>
        <td><strong>3rd</strong> (lowest)</td>
        <td><code>||</code></td>
        <td>OR</td>
        <td>At least one must be true</td>
      </tr>
    </tbody>
  </table>
</div>

This means `!A || B && C` is evaluated as `(!A) || (B && C)` — NOT binds first, then AND, then OR.

<div class="pro-tip">
  <h4>💡 Pro Tip: Use Parentheses</h4>
  <p>Even when precedence is on your side, <strong>always use parentheses</strong> to make your intent clear. Future-you (and your teammates) will thank you. <code>isAdmin || (isLoggedIn && hasPermission)</code> is much clearer than <code>isAdmin || isLoggedIn && hasPermission</code>.</p>
</div>

#### 🎯 Predict the Output: De Morgan's Law

These two expressions look different. Do they produce the same result?

```csharp
bool a = true, b = false;

// Expression 1
bool result1 = !(a && b);

// Expression 2
bool result2 = !a || !b;

Console.WriteLine($"!(a && b)  = {result1}");
Console.WriteLine($"!a || !b   = {result2}");
Console.WriteLine($"Same? {result1 == result2}");
```

<details class="predict-reveal">
<summary>Reveal Answer</summary>
<div class="predict-answer">

**Output:**
```
!(a && b)  = True
!a || !b   = True
Same? True
```

This is **De Morgan's Law** — one of the most important rules in boolean algebra:
- `!(A && B)` is the same as `!A || !B`
- `!(A || B)` is the same as `!A && !B`

🔑 **Key takeaway**: When you "distribute" NOT across AND, it flips to OR (and vice versa). This is how you simplify complex boolean expressions!
</div>
