## 🧠 How Short-Circuit Works

### The `&&` (AND) Short-Circuit

With `&&`, **both sides must be true** for the result to be true. So if the left side is `false`, C# already knows the answer — it skips the right side entirely:

```csharp
// If isLoggedIn is false, C# NEVER checks hasPermission
if (isLoggedIn && hasPermission) {
    Console.WriteLine("Access granted!");
}
```

```
╔═══════════════════════════════════════════════════════╗
║          && SHORT-CIRCUIT                             ║
╠═══════════════════════════════════════════════════════╣
║                                                       ║
║  Left Side    Right Side    Result                    ║
║  ─────────    ──────────    ──────                    ║
║  false        ⚡ SKIPPED    false  (already known!)   ║
║  true         false         false                     ║
║  true         true          true                      ║
║                                                       ║
╚═══════════════════════════════════════════════════════╝
```

### The `||` (OR) Short-Circuit

With `||`, **at least one side must be true**. So if the left side is `true`, C# already knows the answer — it skips the right side:

```csharp
// If isAdmin is true, C# NEVER checks hasSpecialOverride
if (isAdmin || hasSpecialOverride) {
    Console.WriteLine("Elevated access granted!");
}
```

```
╔═══════════════════════════════════════════════════════╗
║          || SHORT-CIRCUIT                             ║
╠═══════════════════════════════════════════════════════╣
║                                                       ║
║  Left Side    Right Side    Result                    ║
║  ─────────    ──────────    ──────                    ║
║  true         ⚡ SKIPPED    true  (already known!)    ║
║  false        true          true                      ║
║  false        false         false                     ║
║                                                       ║
╚═══════════════════════════════════════════════════════╝
```

## 🛡️ The Safety Pattern: Null Checks

Short-circuit evaluation isn't just about performance — it's a **safety mechanism**. The most common use is checking if something exists before accessing it:

```csharp
string name = null;

// ❌ CRASH! Can't call .Length on null
// if (name.Length > 0)

// ✅ Safe! If name is null, .Length is never checked
if (name != null && name.Length > 0) {
    Console.WriteLine($"Hello, {name}!");
}
```

Because `&&` short-circuits, `name.Length` is **never evaluated** when `name` is `null`. Without short-circuiting, this would throw a `NullReferenceException`.

<div class="architect-rule">

#### ⚠️ Architect's Rule: Always Put the Safety Check First

In a `&&` expression, the **left side** should be the check that guards against crashes. Put the null check, bounds check, or existence check on the left.

```csharp
// ✅ Correct order: null check FIRST
if (input != null && input.Length > 5) { ... }

// ❌ Wrong order: .Length crashes if input is null
if (input.Length > 5 && input != null) { ... }  // 💥 CRASH
```

</div>

## 🧩 Combining Short-Circuit Patterns

You can chain multiple short-circuit checks together for robust validation:

```csharp
// All checks short-circuit left to right
if (user != null && user.Email != null && user.Email.Contains("@")) {
    Console.WriteLine($"Valid email: {user.Email}");
}
```

Each `&&` acts as a gate. If any check fails, everything to the right is skipped:
1. Is `user` null? → Stop if yes
2. Is `user.Email` null? → Stop if yes  
3. Does `user.Email` contain "@"? → Only checked if #1 and #2 passed

<div class="pro-tip">
  <h4>💡 Pro Tip: Order Matters for Performance Too</h4>
  <p>Put the <strong>cheapest</strong> or <strong>most likely to fail</strong> check on the left. If 80% of users fail the first check, the expensive second check runs only 20% of the time.</p>
</div>
