## What Is a For Loop?

A **for loop** executes a block of code a **known number of times**, using a counter variable to track progress:

```csharp
for (int i = 0; i < 5; i++) {
    Console.WriteLine($"Iteration {i}");
}

Console.WriteLine("Loop complete.");
```

**Output:**
```
Iteration 0
Iteration 1
Iteration 2
Iteration 3
Iteration 4
Loop complete.
```

The counter starts at `0`, runs while `i < 5`, and increments by one each time. Five iterations — predictable, bounded, and precise.

## The Three Clauses Explained

Every `for` loop header contains exactly three semicolon-separated clauses:

<div class="styled-table-container">
  <table>
    <thead>
      <tr>
        <th>Clause</th>
        <th>Syntax Example</th>
        <th>When It Runs</th>
        <th>Purpose</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td><strong>Initializer</strong></td>
        <td><code>int i = 0</code></td>
        <td>Once, before loop starts</td>
        <td>Declares and initializes the counter variable</td>
      </tr>
      <tr>
        <td><strong>Condition</strong></td>
        <td><code>i &lt; 10</code></td>
        <td>Before each iteration</td>
        <td>Pre-check gate — loop only runs if true</td>
      </tr>
      <tr>
        <td><strong>Iterator</strong></td>
        <td><code>i++</code></td>
        <td>After each iteration</td>
        <td>Advances the counter toward termination</td>
      </tr>
    </tbody>
  </table>
</div>

The `for` loop is **equivalent** to the following `while` loop — it simply consolidates all three control elements onto one line for clarity:

```csharp
// These two loops are identical in behavior:

// for loop version
for (int i = 0; i < 5; i++) {
    Console.WriteLine($"Iteration {i}");
}

// Equivalent while loop
int i = 0;            // initializer
while (i < 5) {       // condition
    Console.WriteLine($"Iteration {i}");
    i++;              // iterator
}
```

<div class="architect-rule">

### Architect's Rule: Counter Scope

The counter variable `i` declared in the `for` loop initializer **only exists inside the loop**. Once the loop ends, `i` is out of scope. If you need the final counter value after the loop, declare it **before** the `for` statement:

```csharp
int i;
for (i = 0; i < 10; i++) { ... }
Console.WriteLine($"Final i: {i}"); // i is accessible here
```

</div>

## The Off-By-One Error

The most common `for` loop failure is the **off-by-one error** — running one too many or one too few iterations. This always comes down to the **initializer** and the **condition boundary**:

```csharp
// INTENT: Print the numbers 1 through 5
// COMMON MISTAKE: starts at 1 but uses < 5 — misses the last value!
for (int i = 1; i < 5; i++) {
    Console.WriteLine(i);
}
// Prints: 1, 2, 3, 4 (MISSING 5)

// CORRECT version 1: start at 1, use <= 5
for (int i = 1; i <= 5; i++) {
    Console.WriteLine(i);
}

// CORRECT version 2: start at 0, use < 5 (zero-based, the canonical pattern)
for (int i = 0; i < 5; i++) {
    Console.WriteLine(i + 1);
}
```

<div class="from-the-field">
  <div class="field-header">
    <span class="field-icon" aria-hidden="true">🏗️</span>
    <h3>From the Field</h3>
  </div>
  <div class="field-content">
    <p><strong>Zero-based indexing is the standard.</strong> In C# (and most modern languages), arrays and collections are indexed starting at 0 — not 1. The canonical for loop pattern <code>for (int i = 0; i &lt; N; i++)</code> aligns perfectly with this. When you start at 0 and use <code>&lt; N</code>, you process exactly N items: i=0, 1, 2, ..., N-1. When you start at 1 and use <code>&lt;= N</code>, you process the same N items but with inconsistent semantics. Senior engineers almost always use zero-based loops. Internalize this pattern now and the off-by-one error becomes rare.</p>
