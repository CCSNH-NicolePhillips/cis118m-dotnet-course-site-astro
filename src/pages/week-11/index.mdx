  <p>
    Last week you built methods that <em>do things</em> — print messages, display status reports, format output. Those were <code>void</code> methods: they perform an action and return nothing. This week you learn methods that <strong>produce things</strong> — methods that compute a value and <strong>send it back</strong> to the caller. The caller captures that value in a variable and uses it for further computation, display, or decision-making.
  </p>
  <p>
    Think of a <code>void</code> method as a department that performs a task (filing a report, sending an email). A <strong>return method</strong> is a department that performs a task <em>and delivers a result</em> — a calculated total, a formatted string, a validated status. The <code>return</code> keyword is the delivery mechanism: it exits the method and hands the result to the caller.
  </p>

## 📤 The Return Contract: Methods That Deliver Results

Last week, methods were action-only — they printed output and returned nothing. This week, methods become **producers**: they compute a result and deliver it to the caller via the `return` keyword. The caller captures that result in a variable and uses it for further work.

<div class="component-cards">
  <div class="component-card">
    <h3>🔇 void Methods (Week 10)</h3>
    <p>Perform an action. Return nothing. The caller cannot store or reuse the result because there is no result. Used for display, logging, and side-effect operations.</p>
    <code>static void PrintTotal(decimal amount) &#123; Console.WriteLine(amount); &#125;</code>
  </div>
  <div class="component-card">
    <h3>📤 Return Methods (Week 11)</h3>
    <p>Compute a value. <strong>Deliver it back</strong> to the caller via the <code>return</code> keyword. The caller stores the result in a variable and uses it. The method's return type declares what kind of value is produced.</p>
    <code>static int Add(int a, int b) &#123; return a + b; &#125;</code>
  </div>
</div>

## 🏗️ Senior Architect Perspective

<div class="architect-rule">

### ⚙️ Return Types Complete the Method Contract

A method signature is a contract. The access modifier says *who can call*. The identifier says *what it does*. The return type says *what it delivers*. When the return type is `void`, the contract says: "I do work, but I hand nothing back." When the return type is `int`, the contract says: "I do work, and I hand back an integer." The `return` keyword fulfills that contract — it exits the method and delivers the promised value.

🎯 **The most common mistake this week will be declaring a return type but forgetting the return statement** — or using `void` when the method should deliver a result. If a method computes something, it should return it. If a method only displays something, it stays void.

</div>
