## void vs Typed Return: The Fundamental Shift

In Week 10, you learned the method signature has three elements: access modifier, return type, and identifier. The return type was always `void`. Now you replace `void` with an actual data type — and add the `return` keyword inside the method body:

```csharp
// Week 10: void — performs an action, returns nothing
static void PrintSum(int a, int b) {
    Console.WriteLine(a + b);   // Displays the result — caller cannot use it
}

// Week 11: int — computes a value and RETURNS it to the caller
static int Add(int a, int b) {
    return a + b;               // Delivers the result — caller can store and use it
}
```

The difference is fundamental: `PrintSum` displays a number on screen — the caller cannot capture, store, or reuse that number. `Add` computes a number and hands it back — the caller stores it in a variable and decides what to do with it.

## The return Keyword: Exit and Deliver

The `return` keyword does two things simultaneously:

1. **Exits the method** — no code after a `return` statement executes
2. **Delivers a value** — the expression after `return` is sent to the caller

```csharp
static int Multiply(int x, int y) {
    return x * y;
    Console.WriteLine("This line never executes");  // Unreachable code
}
```

The compiler will warn you about unreachable code after a `return`. Once `return` executes, the method is done — control jumps back to the caller immediately.

<div class="architect-rule">

### Architect's Rule: The Return Type Is a Promise

When you declare `static int Add(int a, int b)`, you make a promise: this method will deliver an `int` to the caller. The `return` statement fulfills that promise. If you forget the `return` statement, the compiler will not build your program — the promise is broken. If you return a `string` from a method declared `int`, the compiler rejects it — the delivered type does not match the promised type.

```csharp
// COMPILER ERROR: not all code paths return a value
static int GetScore() {
    // Missing return statement — the promise is unfulfilled
}

// COMPILER ERROR: cannot convert string to int
static int GetScore() {
    return "ninety-five";  // Wrong type returned
}

// CORRECT: return type matches the declared type
static int GetScore() {
    return 95;             // Promise fulfilled
}
```

</div>

## Common Return Types

You can return any data type. The return type in the signature must match the type of the value in the `return` statement:

| Return Type | What the Method Delivers | Example |
|-------------|--------------------------|---------|
| `int` | A whole number | `return 42;` |
| `double` | A decimal number | `return 3.14159;` |
| `string` | A text value | `return "Hello";` |
| `bool` | A true/false value | `return age >= 18;` |
| `decimal` | A precise monetary value | `return 99.95m;` |

```csharp
static double CalculateCircleArea(double radius) {
    return Math.PI * radius * radius;
}

static string FormatGreeting(string name) {
    return $"Welcome aboard, {name}!";
}

static bool IsEligible(int age) {
    return age >= 18;
}
```

Each method computes a result and delivers it. The caller decides what to do with the returned value — print it, store it, pass it to another method, or use it in a condition.

## void Methods Cannot Be Assigned

A `void` method returns nothing. Attempting to store its result causes a compiler error:

```csharp
// void method — performs an action only
static void PrintMessage(string msg) {
    Console.WriteLine(msg);
}

// COMPILER ERROR: cannot assign void to a variable
string result = PrintMessage("Hello");  // ERROR

// CORRECT: call void methods as standalone statements
PrintMessage("Hello");                  // No assignment — just call it
```

This is the key decision you must make when designing a method: **Does the caller need the result?** If yes, use a typed return. If the method only displays or logs, use `void`.

| Nothing — just display | `static void Print(...)` |

## Multiple return Statements: Conditional Returns

A method can have multiple `return` statements inside `if/else` branches. The first `return` that executes exits the method:

```csharp
static string GetGradeLabel(int score) {
    if (score >= 90) {
        return "A";
    } else if (score >= 80) {
        return "B";
    } else if (score >= 70) {
        return "C";
    } else {
        return "F";
    }
}
```

Every possible code path must end with a `return` statement. If the compiler detects any path that could exit without returning, it produces an error: "not all code paths return a value."

## Summary: The Return Statement

| Concept | Description |
|---------|-------------|
| Return Type | Declares what kind of value the method delivers (`int`, `double`, `string`, `bool`) |
| `void` | Special return type meaning "no value returned" |
| `return` keyword | Exits the method and delivers the value to the caller |
| Return contract | The returned value must match the declared return type |
| Unreachable code | Code after a `return` statement never executes |
