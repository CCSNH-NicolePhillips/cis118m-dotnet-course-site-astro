## The Assignment Pattern

When a method returns a value, the call appears on the **right side** of an assignment statement. The variable on the left receives the returned value:

```csharp
int result = Add(10, 25);    // Add returns 35 → stored in result
Console.WriteLine(result);    // Prints: 35
```

This is the **result capture pattern**: `type variableName = MethodCall(arguments);`. The variable type must match the method's declared return type — `int` method → `int` variable, `string` method → `string` variable.

---

## The Variable Is Independent of the Method

Once the returned value is stored in a variable, it is completely independent of the method. The variable holds a copy of the result — modifying the variable does not affect the method, and calling the method again does not change the variable:

```csharp
int total = Add(10, 20);     // total = 30
total = total + 5;            // total = 35 — modifying the variable, not the method
Console.WriteLine(total);     // Prints: 35

int otherTotal = Add(100, 200);  // otherTotal = 300 — a separate call, separate result
Console.WriteLine(otherTotal);   // Prints: 300

static int Add(int a, int b) {
    return a + b;
}
```

Each call produces an independent value. Each assignment stores that value in a separate variable. The method has no memory of previous calls — it computes fresh every time.

## Using Captured Results in Expressions

A captured result can be used anywhere a value of that type is valid — in arithmetic, conditions, string interpolation, or as an argument to another method call:

```csharp
// Arithmetic
int width = 10;
int height = 5;
int area = CalculateArea(width, height);     // area = 50
int doubleArea = area * 2;                    // doubleArea = 100

// String interpolation
string greeting = FormatGreeting("Jordan");
Console.WriteLine($"Message: {greeting}");

// Decision-making
bool eligible = IsOldEnough(21);
if (eligible) {
    Console.WriteLine("Access granted.");
}

// As an argument to another method
int perimeter = CalculatePerimeter(width, height);
DisplayResult("Perimeter", perimeter);

// METHOD DEFINITIONS
static int CalculateArea(int w, int h) {
    return w * h;
}

static int CalculatePerimeter(int w, int h) {
    return 2 * (w + h);
}

static string FormatGreeting(string name) {
    return $"Welcome aboard, {name}!";
}

static bool IsOldEnough(int age) {
    return age >= 18;
}

static void DisplayResult(string label, int value) {
    Console.WriteLine($"{label}: {value}");
}
```

The captured variable behaves exactly like any other variable — it can be printed, compared, passed as an argument, or used in calculations.

<div class="architect-rule">

### Architect's Rule: Capture, Then Use — Separation of Concerns

The pattern `type result = Method(args);` followed by `Console.WriteLine(result);` separates **computation** from **display**. The method computes. The caller decides how to use the result. This is a core principle called **separation of concerns** — each unit of code has one responsibility. The method does not need to know how its result will be used. The caller does not need to know how the result was computed.

```csharp
// GOOD: computation separated from display
double converted = CelsiusToFahrenheit(100.0);
Console.WriteLine($"Temperature: {converted:F1}°F");

// ALSO VALID: inline form (skip the variable)
Console.WriteLine($"Temperature: {CelsiusToFahrenheit(100.0):F1}°F");

// But the first form is clearer when the result is used in multiple places
```

</div>

## Inline Calls vs Variable Capture

<img src="/media/week%2011/11.2/Inline%20vs%20Capture.jpeg" alt="Side-by-side comparison showing variable capture on the left where a return value is stored in a named variable versus an inline call on the right where the method call is used directly in an expression" style="max-width: 100%; border-radius: 12px; margin: 24px 0;" />

You do not always need to store the return value in a named variable. You can use the method call directly in an expression — this is called an **inline call**:

```csharp
// Variable capture — clear, debuggable, reusable
int total = Add(10, 20);
Console.WriteLine(total);

// Inline call — compact, but the value cannot be reused
Console.WriteLine(Add(10, 20));

// Inline in a condition
if (IsOldEnough(25)) {
    Console.WriteLine("Eligible.");
}
```

Both approaches are valid. Use **variable capture** when:
- The result is used more than once
- You want to inspect the value during debugging
- The expression is complex and a named variable improves readability

Use **inline calls** when:
- The result is used exactly once
- The method name makes the intent clear

## Chaining Results: Method Call as Argument

A method's return value can be passed directly as an argument to another method. This is called **chaining**:

```csharp
// Chain: Add returns 30, which becomes the argument to Double
int result = Double(Add(10, 20));    // Double(30) → 60
Console.WriteLine(result);           // Prints: 60

static int Add(int a, int b) {
    return a + b;
}

static int Double(int value) {
    return value * 2;
}
```

The inner method (`Add`) executes first, returns its value, and that value becomes the argument to the outer method (`Double`). This is powerful but can become hard to read — when a chain involves more than two method calls, use intermediate variables for clarity.

---

## Ignoring a Return Value

You are not required to capture a return value. C# allows you to call a return-type method without storing the result — but the value is discarded:

```csharp
Add(10, 20);  // The method runs, returns 30, but the value is thrown away
```

This is legal but usually wasteful. If you call a method that computes something and throw away the result, you are paying the cost of computation for nothing. In most cases, if you do not need the return value, you should be calling a `void` method instead.

## Type Mismatch: The Variable Must Match the Return Type

The variable that receives the returned value must be declared with the same type (or a compatible type) as the method's return type:

```csharp
// CORRECT: int method → int variable
int total = Add(10, 20);

// CORRECT: double method → double variable
double temp = CelsiusToFahrenheit(100.0);

// COMPILER ERROR: int method → string variable
string text = Add(10, 20);  // Cannot convert int to string

// CORRECT: compatible widening — int → double
double widened = Add(10, 20);  // int 30 automatically widens to double 30.0
```

## Practical Architecture: A Multi-Step Calculation

The following program demonstrates the full result-capture workflow — compute, capture, use, and display:

```csharp
double price = 49.99;
int quantity = 3;

double subtotal = CalculateSubtotal(price, quantity);
double tax = CalculateTax(subtotal, 0.08);
double total = subtotal + tax;
string receipt = FormatReceipt(subtotal, tax, total);

Console.WriteLine(receipt);

// METHOD DEFINITIONS
static double CalculateSubtotal(double unitPrice, int qty) {
    return unitPrice * qty;
}

static double CalculateTax(double amount, double taxRate) {
    return amount * taxRate;
}

static string FormatReceipt(double subtotal, double tax, double total) {
    return $"Subtotal: {subtotal:C}\nTax: {tax:C}\nTotal: {total:C}";
}
```

**Output:**
```
Subtotal: $149.97
Tax: $12.00
Total: $161.97
```

Each method handles one computation. `Main` orchestrates the workflow by capturing each result and feeding it into the next step. Changing the tax rate, receipt format, or subtotal logic requires updating only the affected method.
