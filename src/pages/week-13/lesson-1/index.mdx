## <span aria-hidden="true">🧠</span> Array Syntax and Indexing

An array stores multiple values of the same type in a fixed-size sequence. C# array declaration follows this exact pattern:

```csharp
Student[] roster = new Student[3];
```

This line does three things:
1. **Declares a variable** `roster` whose type is "array of Student"
2. **Allocates memory** for exactly 3 Student slots using `new`
3. **Initializes all slots** to `null` — no Student objects exist yet

`roster` now contains three slots indexed `0`, `1`, and `2`. Each slot can hold a reference to a `Student` object, but the slots are **empty until you assign objects to them**. This is the fundamental difference between declaring an array and filling it — the container exists, but it starts with nothing inside.

## <span aria-hidden="true">🏗️</span> Zero-Based Indexing and .Length

Array positions start at `0`, not `1`. The last valid index is always `array.Length - 1`. This is not arbitrary — it mirrors how memory offsets work at the hardware level. The first element is at offset 0 from the base address.

<img src="/media/week%2013/13.1/Zero-Based%20Index%20Map.jpeg" alt="Zero-based index map showing five array slots labeled index 0 through 4 with corresponding human positions 1st through 5th and warnings about starting at index 1" style="max-width: 100%; border-radius: 12px; margin: 24px 0;" />

After creating an array, you fill it by assigning objects to specific indexes. Each assignment places one `Student` object into one numbered slot:

```csharp
Student[] roster = new Student[3];

roster[0] = new Student { Name = "Ada", Id = 1001, Gpa = 3.9 };
roster[1] = new Student { Name = "Alan", Id = 1002, Gpa = 3.7 };
roster[2] = new Student { Name = "Grace", Id = 1003, Gpa = 4.0 };

for (int i = 0; i < roster.Length; i++) {
    Console.WriteLine($"{roster[i].Name} ({roster[i].Id}) GPA: {roster[i].Gpa}");
}
```

The `for` loop uses `i < roster.Length` as its boundary. This ensures the loop stops at the last valid index (`2` for a 3-element array) and never attempts to access `roster[3]`, which would throw an `IndexOutOfRangeException`.

<div class="architect-rule">

#### <span aria-hidden="true">⚠️</span> Architect’s Rule: Always Use .Length for Bounds

Bound checks should always be expressed with <code>.Length</code>, not hard-coded constants. If the array capacity changes from 3 to 5, a hard-coded <code>i &lt; 3</code> silently skips the new elements. A <code>.Length</code>-based bound stays correct automatically. Hard-coded bounds create maintenance defects and out-of-range exceptions in production.

</div>

<img src="/media/week%2013/13.1/Length%20Boundary%20Guard.jpeg" alt="Loop boundary safety diagram comparing i less than roster Length as valid iteration and i equals roster Length as out-of-range access condition" style="max-width: 100%; border-radius: 12px; margin: 24px 0;" />

<div class="pro-tip">
  <h4><span aria-hidden="true">💡</span> Pro Tip: Default Values in Unassigned Slots</h4>
  <p>When you create an array with <code>new Student[5]</code> but only fill 3 slots, the remaining 2 slots contain <code>null</code>. Attempting to access a property on a <code>null</code> slot (<code>roster[4].Name</code>) throws a <code>NullReferenceException</code>. Always either fill every slot or check for <code>null</code> before accessing properties.</p>
</div>

## <span aria-hidden="true">🔀</span> Foreach with Arrays of Class Objects

Use `foreach` when you need sequential read access without index math. The `foreach` loop automatically walks through every element in the array from index `0` to `Length - 1`:

```csharp
foreach (Student student in roster) {
    Console.WriteLine($"{student.Name} | {student.Id} | {student.Gpa}");
}
```

Each iteration assigns the current element to the loop variable `student`. You don't manage an index counter, and you can't accidentally go out of bounds. The tradeoff is that `foreach` provides **read-only sequential access** — you cannot modify the array or skip elements during iteration.

When should you use `for` vs `foreach`? Use `for` when you need the index (to modify elements, access neighbors, or skip positions). Use `foreach` when you simply need to process every element in order. For Week 13's reporting workflows — printing every student in a roster — `foreach` is the correct tool.

## <span aria-hidden="true">📐</span> Array Declaration Patterns

C# offers multiple ways to declare and initialize arrays. The pattern you use depends on whether you know the values at declaration time:

```csharp
// Pattern 1: Declare then fill (when values come later)
Student[] roster = new Student[3];
roster[0] = new Student { Name = "Ada", Id = 1001, Gpa = 3.9 };

// Pattern 2: Inline initialization (when values are known upfront)
int[] scores = new int[] { 95, 87, 92, 78, 100 };

// Pattern 3: Shorthand (compiler infers the type)
string[] names = { "Ada", "Alan", "Grace" };
```

Pattern 1 is the standard for object arrays — you create the container first, then construct each object individually. Patterns 2 and 3 work best for primitive types where the values are known at compile time.
