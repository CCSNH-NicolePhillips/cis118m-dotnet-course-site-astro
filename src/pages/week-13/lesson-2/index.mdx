## <span aria-hidden="true">🧠</span> Namespace Requirement

`List<T>` lives in `System.Collections.Generic`. This namespace must be imported at the top of your file before you can use any generic collection type:

```csharp
using System.Collections.Generic;
```

Without this line, the compiler does not recognize `List<T>` and reports an error. Think of it as unlocking the collections toolbox — the tools exist in the framework, but your code cannot see them until you import the namespace. This is the same pattern as `using System;` for `Console` — C# organizes functionality into namespaces to prevent name collisions and keep the global scope clean.

## <span aria-hidden="true">🏗️</span> Core List\<T\> Operations

A `List<T>` starts empty and grows as you add elements. Unlike an array, there is no capacity declaration — the list manages its own internal storage:

```csharp
using System.Collections.Generic;

List<Student> students = new List<Student>();
students.Add(new Student { Name = "Ada", Id = 1001, Gpa = 3.9 });
students.Add(new Student { Name = "Alan", Id = 1002, Gpa = 3.7 });

Console.WriteLine("Count: " + students.Count);

students.Remove(students[1]);
Console.WriteLine("Count after removal: " + students.Count);
```

Three operations define the `List<T>` lifecycle:
1. **`.Add(item)`** — appends one element to the end of the list, increasing `Count` by 1
2. **`.Remove(item)`** — finds and removes the first matching element, decreasing `Count` by 1
3. **`.Count`** — returns the current number of elements (not maximum capacity)

Notice `.Count` is a **property** (no parentheses), not a method. It reflects the live state of the list — after every `.Add()` it increases, after every `.Remove()` it decreases.

## <span aria-hidden="true">🔀</span> Foreach Integration with Week 12 Class Objects

`foreach` works directly with `List<Student>` and provides clean object traversal. The syntax is identical to arrays — `foreach` does not care whether the underlying collection is an array or a list:

```csharp
List<Student> students = new List<Student>();
students.Add(new Student { Name = "Ada Lovelace", Id = 1001, Gpa = 3.9 });
students.Add(new Student { Name = "Grace Hopper", Id = 1003, Gpa = 4.0 });

foreach (Student student in students) {
    Console.WriteLine($"{student.Name} ({student.Id}) GPA: {student.Gpa}");
}
```

This is the power of C#'s collection model: both arrays and lists implement the same iteration interface. Code that uses `foreach` to process a collection works whether the data lives in a `Student[]` or a `List<Student>`. The loop variable `student` receives each element in order, and you access properties with the same dot operator from Week 12.

<div class="architect-rule">

#### <span aria-hidden="true">⚠️</span> Architect’s Rule: Use foreach for Reads, for Loops for Mutation

Use `foreach` for full-sequence reads and reporting workflows. Use index-based `for` loops only when positional mutation is required — such as replacing an element at a specific position. This division improves readability and reduces off-by-one errors. Never modify a list's contents (Add/Remove) while iterating it with `foreach` — this throws an `InvalidOperationException`.

</div>

<div class="pro-tip">
  <h4><span aria-hidden="true">💡</span> Pro Tip: .Count vs .Length</h4>
  <p>Arrays use <code>.Length</code> (a fixed property set at creation). Lists use <code>.Count</code> (a live property that changes with Add/Remove). If you accidentally write <code>students.Length</code> on a list, the compiler will catch it — but knowing the distinction prevents confusion. Remember: <strong>arrays are fixed → Length</strong>, <strong>lists are dynamic → Count</strong>.</p>
</div>

## <span aria-hidden="true">📐</span> Array vs. List: When to Use Which

Choosing between `Student[]` and `List<Student>` is a design decision. Neither is universally better — each fits different requirements:

<div class="styled-table-container">
  <table>
    <thead>
      <tr>
        <th>Criteria</th>
        <th>Student[] (Array)</th>
        <th>List&lt;Student&gt;</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td><strong>Capacity</strong></td>
        <td>Fixed at creation — cannot grow or shrink</td>
        <td>Dynamic — grows with .Add(), shrinks with .Remove()</td>
      </tr>
      <tr>
        <td><strong>Size property</strong></td>
        <td><code>.Length</code> (never changes)</td>
        <td><code>.Count</code> (changes with every Add/Remove)</td>
      </tr>
      <tr>
        <td><strong>Best for</strong></td>
        <td>Known, fixed datasets (days of week, RGB channels)</td>
        <td>Unknown or changing datasets (user registrations, orders)</td>
      </tr>
      <tr>
        <td><strong>Performance</strong></td>
        <td>Slightly faster — no resize overhead</td>
        <td>Slightly slower — occasional internal resizing</td>
      </tr>
      <tr>
        <td><strong>Namespace</strong></td>
        <td>Built-in — no using directive needed</td>
        <td>Requires <code>using System.Collections.Generic;</code></td>
      </tr>
    </tbody>
  </table>
</div>

In professional C# code, `List<T>` is the default choice for most scenarios. Arrays are used when the size is truly fixed and known at compile time (like the 12 months in a year) or when performance-critical code needs the minimal overhead of a raw array.
