## Parameters vs Arguments

These two terms describe the same data at two different points in the program:

| Term | Location | Description |
|------|----------|-------------|
| **Parameter** | Method signature (definition) | The typed variable that receives data when called |
| **Argument** | Method call (call site) | The actual value passed into the method |

```csharp
// "name" is the PARAMETER — declared in the signature
static void Greet(string name)
{
    Console.WriteLine($"Hello, {name}.");
}

static void Main()
{
    Greet("Alice");   // "Alice" is the ARGUMENT — passed at the call site
    Greet("Bob");     // "Bob" is the ARGUMENT on this call
}
```

**Output:**
```
Hello, Alice.
Hello, Bob.
```

The same method, two different behaviors — driven entirely by the argument passed on each call.

## Multiple Parameters

A method can declare multiple parameters, separated by commas. Each parameter has its own type and name. Arguments at the call site must match the parameters in **count, order, and type**:

```csharp
static void PrintItemPrice(string item, decimal price)
{
    Console.WriteLine($"{item}: {price:C}");
}

static void Main()
{
    PrintItemPrice("Laptop", 1299.99m);
    PrintItemPrice("Monitor", 399.00m);
    PrintItemPrice("Keyboard", 89.95m);
}
```

**Output:**
```
Laptop: $1,299.99
Monitor: $399.00
Keyboard: $89.95
```

<div class="architect-rule">

### Architect's Rule: Argument Order Is Positional

Arguments are matched to parameters by position — not by name. The first argument maps to the first parameter, the second to the second, and so on. Passing them in the wrong order does not cause a compile error if the types happen to match — it produces wrong output silently:

```csharp
static void PrintItemPrice(string item, decimal price) { ... }

// CORRECT: string first, decimal second
PrintItemPrice("Laptop", 1299.99m);

// WRONG: decimal first, string second — compiler error (type mismatch in this case)
PrintItemPrice(1299.99m, "Laptop");
```

When parameters have the same type (e.g., two `int` parameters), a reversed argument order will compile but produce incorrect results. Always verify order at the call site against the signature.

</div>

## The DRY Principle: Don't Repeat Yourself

Before parameters, you might write separate methods for every variation of a task:

```csharp
// WITHOUT parameters — repetition
static void PrintAliceGreeting()   { Console.WriteLine("Hello, Alice."); }
static void PrintBobGreeting()     { Console.WriteLine("Hello, Bob."); }
static void PrintCarlosGreeting()  { Console.WriteLine("Hello, Carlos."); }
```

This violates the **DRY Principle** — the same structure appears three times. If the greeting format changes, you must update three methods. The correct architecture has one method, parameterized:

```csharp
// WITH parameters — DRY
static void Greet(string name)
{
    Console.WriteLine($"Hello, {name}.");
}
```

Change the format once; it applies to every call. This is not just a style preference — it is a **maintenance contract**. A codebase that repeats logic accumulates inconsistencies over time as some copies get updated and others are missed.

## Passing Variables as Arguments

Arguments do not have to be literals — you can pass any expression of the correct type, including variables:

```csharp
static void DisplayScore(string playerName, int score)
{
    Console.WriteLine($"{playerName}: {score} points");
}

static void Main()
{
    string player = Console.ReadLine();
    int earned = 450;

    DisplayScore(player, earned);      // Variables as arguments
    DisplayScore("Computer", 300);     // Literals as arguments
    DisplayScore(player, earned + 50); // Expression as argument
}
```

The argument is evaluated at the call site — whatever value `earned` holds at that moment, that value is passed into the `score` parameter.

---

## Parameters Are Local to the Method

A parameter variable exists only for the duration of the method call. It is created when the method is invoked, receives the argument value, and is destroyed when the method returns. It is not the same variable as anything in the calling code — it is a separate copy:

```csharp
static void Double(int x)
{
    x = x * 2;   // Modifies the local copy only
    Console.WriteLine($"Inside Double: {x}");
}

static void Main()
{
    int value = 10;
    Double(value);
    Console.WriteLine($"After call: {value}");  // Still 10
}
```

**Output:**
```
Inside Double: 20
After call: 10
```

The `value` variable in `Main` is unchanged because the method received a **copy** of the value, not the variable itself. This is called **pass-by-value**, which is the default behavior for all value types (`int`, `double`, `decimal`, `bool`) in C#.

## Practical Architecture: A Multi-Parameter Report

The following program demonstrates a complete parameterized design — `Main` collects data and calls methods, each method handles a specific output task:

```csharp
static void Main()
{
    string employeeName = "Jordan Reyes";
    int hoursWorked = 42;
    decimal hourlyRate = 28.50m;
    decimal total = hoursWorked * hourlyRate;

    PrintPaystubHeader(employeeName);
    PrintPayLine("Hours Worked", hoursWorked.ToString());
    PrintPayLine("Hourly Rate", hourlyRate.ToString("C"));
    PrintPayLine("Gross Pay", total.ToString("C"));
    PrintPaystubFooter();
}

static void PrintPaystubHeader(string name)
{
    Console.WriteLine("=== PAY STATEMENT ===");
    Console.WriteLine($"Employee: {name}");
    Console.WriteLine("---------------------");
}

static void PrintPayLine(string label, string value)
{
    Console.WriteLine($"{label,-20} {value,10}");
}

static void PrintPaystubFooter()
{
    Console.WriteLine("---------------------");
    Console.WriteLine("Payment Processed.");
}
```

`Main` is an orchestrator — it holds the data and directs the workflow. Each method handles exactly one display task. If the pay stub format changes, only the affected method needs updating.

## Summary: Parameters and the DRY Principle

| Concept | Definition |
|---------|-----------|
| Parameter | Typed variable in the method signature — receives data on each call |
| Argument | The actual value passed at the call site |
| Pass-by-value | Method receives a copy of the argument — original is unchanged |
| DRY Principle | Don't Repeat Yourself — logic exists in one place, called many times |
