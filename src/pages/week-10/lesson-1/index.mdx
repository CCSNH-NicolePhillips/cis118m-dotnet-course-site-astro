## The Three Elements of a Method Signature

A method signature has exactly three required elements. Every method you write — from the simplest printer to a complex calculation engine — must declare all three:

```csharp
static void PrintHeader() {
    Console.WriteLine("=== SYSTEM REPORT ===");
}
```

## Element 1: The Access Modifier

The **access modifier** controls which code is allowed to call this method. In top-level C# programs, all custom methods must be declared `static` because `Main` is static — it can only call other static members directly.

```csharp
// static — accessible from Main and any other static method in the class
static void DisplayWelcome() {
    Console.WriteLine("System initialized.");
}
```

<div class="architect-rule">

### Architect's Rule: static in Top-Level Programs

When you write a top-level C# program (no explicit class declaration), the compiler generates a class behind the scenes and makes `Main` a static method. Every helper method you define must also be `static` to be callable from `Main`. This is not a restriction unique to beginners — static methods are the standard architecture for utility and helper functions throughout the .NET ecosystem.

</div>

## Element 2: The Return Type

The **return type** declares what data type the method sends back to the caller when it finishes. There are two categories:

| Return Type | Meaning | Example Use |
|-------------|---------|-------------|
| `void` | Method returns nothing — performs an action only | Printing output, displaying a menu |
| `int`, `string`, `bool`, `double`, etc. | Method computes and returns a value of that type | Calculating totals, formatting text |

This section focuses on `void` methods. Return types that produce values are covered in Week 11.

```csharp
// void — this method prints, it does not produce a returnable value
static void PrintSeparator() {
    Console.WriteLine("----------------------------");
}

// void — display methods perform actions, they do not calculate results
static void PrintFooter() {
    Console.WriteLine("Report complete.");
}
```

### Calling a void Method

A `void` method is called as a standalone statement — it is not assigned to a variable because it returns no value:

```csharp
PrintHeader();      // Calls PrintHeader — executes its body, then returns here
PrintSeparator();   // Calls PrintSeparator — same pattern
PrintFooter();      // Calls PrintFooter

// CUSTOM METHOD DEFINITIONS — always below top-level statements
static void PrintHeader() {
    Console.WriteLine("=== SYSTEM REPORT ===");
}

static void PrintSeparator() {
    Console.WriteLine("----------------------------");
}

static void PrintFooter() {
    Console.WriteLine("Report complete.");
}
```

**Output:**
```
=== SYSTEM REPORT ===
----------------------------
Report complete.
```

`Main` calls three methods in sequence. Each method executes its body and returns control to the next line after the call in `Main`.

---

## Element 3: The Identifier

The **identifier** is the name of the method. C# method names follow **PascalCase** — every word is capitalized, including the first:

```csharp
static void PrintWelcome()    // Correct: PascalCase
static void printWelcome()    // Wrong: camelCase (variable naming convention)
static void print_welcome()   // Wrong: snake_case (not C# convention)
static void p()               // Wrong: not descriptive
```

A good identifier is a **verb phrase** that describes what the method does:

| Good Identifier | Why It Works |
|----------------|-------------|
| `PrintHeader` | Clear action — prints something called Header |
| `DisplayMenu` | Clear action — displays a menu |
| `ShowSummary` | Clear action — shows a summary |
| `ResetCounter` | Clear action — resets something called Counter |

## Execution Flow: The Call Stack

When a method is called, program execution leaves `Main`, enters the method body, executes every statement in the method, and then returns to the line immediately after the call. This is **sequential execution across method boundaries**:

<img src="/media/week%2010/10.1/Call%20Stack%20Flow.jpeg" alt="Call Stack Flow — arrows showing program execution jumping from Main into a method body and returning back after the method completes" style="max-width: 100%; border-radius: 12px; margin: 24px 0;" />

```csharp
Console.WriteLine("Start of Main");   // 1. Executes
SayHello();                           // 2. Jumps to SayHello
Console.WriteLine("Back in Main");    // 4. Resumes here after SayHello returns

static void SayHello() {
    Console.WriteLine("Inside SayHello"); // 3. Executes inside the method
}
```

**Output:**
```
Start of Main
Inside SayHello
Back in Main
```

<div class="architect-rule">

### Architect's Rule: Method Placement in Top-Level Programs

In a top-level C# program, custom methods are defined **after** the top-level statements (i.e., after your `Main` logic). The compiler enforces this — you cannot interleave method definitions with top-level statements. Place all custom method definitions at the bottom of the file, below the last top-level statement.

<img src="/media/week%2010/10.1/Method%20Placement.jpeg" alt="Method Placement — a code file split into two zones: top-level statements on top, custom method definitions on the bottom, with a clear dividing line between them" style="max-width: 100%; border-radius: 12px; margin: 24px 0;" />

```csharp
// TOP-LEVEL STATEMENTS (your Main logic)
PrintHeader();
Console.WriteLine("Hello");
PrintFooter();

// CUSTOM METHOD DEFINITIONS — always below top-level statements
static void PrintHeader() {
    Console.WriteLine("=== REPORT ===");
}

static void PrintFooter() {
    Console.WriteLine("=== END ===");
}
```

</div>

## Reusability: Call a Method More Than Once

The defining advantage of a method is that it can be **called multiple times** without repeating its code. The method body is written once; calling it is a single line each time:

```csharp
PrintSeparator();
Console.WriteLine("Section 1: Initialization");
PrintSeparator();
Console.WriteLine("Section 2: Processing");
PrintSeparator();
Console.WriteLine("Section 3: Summary");
PrintSeparator();

static void PrintSeparator() {
    Console.WriteLine("==============================");
}
```

**Output:**
```
==============================
Section 1: Initialization
==============================
Section 2: Processing
==============================
Section 3: Summary
==============================
```

`PrintSeparator` is defined once and called four times. If the separator format needs to change, you update it in exactly one place.

## Summary: The Method Signature Contract

| Element | Keyword(s) | Purpose |
|---------|-----------|---------|
| Access Modifier | `static` | Makes the method callable from `Main` in top-level programs |
| Return Type | `void` (this week) | Declares the method produces no return value |
| Identifier | `PascalCase` name | Names the method — a verb phrase describing the action |
