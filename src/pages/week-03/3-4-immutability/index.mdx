<h3>Compile-Time Inlining</h3>
<p>When you mark a value as <code>const</code>, the Roslyn compiler performs a <strong>'Find and Replace'</strong> across your entire project. It doesn't look up the value at runtime; it literally replaces every mention of your constant with the raw number or text.</p>

<ul>
  <li><strong>Allowed:</strong> <code>int</code>, <code>double</code>, <code>bool</code>, <code>char</code>, <code>string</code>, and <code>decimal</code>.</li>

## �🔐 Why Make Values Unchangeable?

Some values should **never change** during program execution:

- Mathematical constants (π = 3.14159...)
- Configuration settings (MAX_CONNECTIONS = 100)
- Fixed rates (TAX_RATE = 0.0725)

Making these values **immutable** (unchangeable) prevents bugs and makes your intent clear.

---

## 🎯 The const Keyword

Use `const` to create a compile-time constant—a value that is **baked into your program** when it's built.

```csharp
const double PI = 3.14159265359;
const int MAX_ATTEMPTS = 3;
const string APP_NAME = "SystemMonitor";
```

### Rules for const:
1. Must be assigned at declaration
2. Value must be known at compile time
3. Cannot be changed after declaration

## 📝 Naming Convention: UPPER_CASE

By convention, constants use `UPPER_CASE` with underscores:

```csharp
const int MAX_CONNECTIONS = 100;     // ✅ Clear it's a constant
const double TAX_RATE = 0.0725;      // ✅ Clear it's a constant
const string API_KEY = "abc123";     // ✅ Clear it's a constant

const int maxConnections = 100;      // ⚠️ Works, but not conventional
```

This naming pattern immediately signals to developers: "This value never changes."
