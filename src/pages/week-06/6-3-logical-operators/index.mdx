## ⚡ The Three Logical Operators

| Operator | Name | Meaning | Example |
|----------|------|---------|---------|
| `&&` | **AND** | Both must be true | `age >= 18 && hasID` |
| `\|\|` | **OR** | At least one must be true | `isAdmin \|\| isModerator` |
| `!` | **NOT** | Reverses the value | `!isLocked` |

---

## 🔌 AND (&&): Both Must Pass

The `&&` operator returns `true` only when **both** conditions are true. Think of two switches in **series** — both must be ON for current to flow:

```csharp
int age = 21;
bool hasID = true;

if (age >= 18 && hasID) {
    Console.WriteLine("✅ Entry granted.");
} else {
    Console.WriteLine("❌ Entry denied.");
}
```

### AND Truth Table

| Left | Right | Result |
|------|-------|--------|
| `true` | `true` | `true` ✅ |
| `true` | `false` | `false` ❌ |
| `false` | `true` | `false` ❌ |
| `false` | `false` | `false` ❌ |

**Key insight**: AND is strict — if **either** side is false, the whole thing is false.

---

## 🔌 OR (||): At Least One Must Pass

The `||` operator returns `true` when **at least one** condition is true. Think of two switches in **parallel** — if either is ON, current flows:

```csharp
bool isAdmin = false;
bool isModerator = true;

if (isAdmin || isModerator) {
    Console.WriteLine("🔑 You have moderation privileges.");
} else {
    Console.WriteLine("🔒 Standard user access only.");
}
```

### OR Truth Table

| Left | Right | Result |
|------|-------|--------|
| `true` | `true` | `true` ✅ |
| `true` | `false` | `true` ✅ |
| `false` | `true` | `true` ✅ |
| `false` | `false` | `false` ❌ |

**Key insight**: OR is generous — if **either** side is true, the whole thing is true. Only fails when BOTH are false.

---

## 🔌 NOT (!): Flip the Switch

The `!` operator **reverses** a boolean value. True becomes false, false becomes true:

```csharp
bool isLocked = false;

if (!isLocked) {
    Console.WriteLine("🔓 Door is unlocked — you may enter.");
}
// !false evaluates to true, so the message prints
```

## 🧠 Short-Circuit Evaluation

C# is smart about logical operators. It **stops evaluating** as soon as it knows the answer:

- **AND (`&&`)**: If the left side is `false`, the right side is **never checked** (because the result is already `false`)
- **OR (`||`)**: If the left side is `true`, the right side is **never checked** (because the result is already `true`)

```csharp
string input = null;

// SAFE — the second condition only runs if input is NOT null
if (input != null && input.Length > 0) {
    Console.WriteLine("Input has content.");
}
// Without short-circuit, input.Length would crash on null!
```

This is called **short-circuit evaluation** and it's not just an optimization — it's a critical safety feature.

## 🔬 Try It: Operator Precedence

NOT (`!`) binds tighter than AND (`&&`), which binds tighter than OR (`||`). Use parentheses to make your intent clear:

<TryItNowRunner 
  starterId="week-06-lesson-1" 
  height={400}
  code={`using System;

class Program
{
    static void Main()
    {
        bool isWeekend = true;
        bool isHoliday = false;
        bool hasDeadline = true;
        
        // Without parentheses — hard to read
        // && binds tighter than ||
        bool canRelax1 = isWeekend || isHoliday && !hasDeadline;
        
        // With parentheses — intent is CLEAR
        bool canRelax2 = (isWeekend || isHoliday) && !hasDeadline;
        
        Console.WriteLine($"Weekend: {isWeekend}");
        Console.WriteLine($"Holiday: {isHoliday}");
        Console.WriteLine($"Has Deadline: {hasDeadline}");
        Console.WriteLine();
        Console.WriteLine($"canRelax (no parens):   {canRelax1}");
        Console.WriteLine($"canRelax (with parens): {canRelax2}");
        Console.WriteLine();
        Console.WriteLine("The parentheses change the result!");
        Console.WriteLine("Always use parentheses to make intent clear.");
    }
}`}
  instructions="Notice how parentheses change the result! The first expression evaluates && before ||, the second groups differently." 
/>

<div class="architect-rule">

#### 🏗️ Architect's Rule: Parenthesize for Clarity

Even when you know the precedence rules, **use parentheses** to make your intent obvious. Future you (and your teammates) will thank you.

```csharp
// ❌  Relies on precedence knowledge
if (a || b && c)

// ✅  Intent is crystal clear  
if (a || (b && c))
```
